# Android-приложение «ДИПСИК ХУДОЖНИК»

Приложение, в котором ты пишешь, что нарисовать, а **DeepSeek пишет код картины,
и Python-движок `dipkit` рисует PNG прямо на телефоне**. Никаких серверов:
после генерации кода рендер идёт локально.

```
┌──────────────────────────────────────────┐
│ Kotlin + Jetpack Compose                 │   экран: запрос, стиль, размер, галерея
│   MainActivity.kt                        │
└────────────────┬─────────────────────────┘
                 │ ArtistBridge.kt — одна JSON-строка туда, одна обратно
┌────────────────▼─────────────────────────┐
│ Chaquopy: CPython 3.12 внутри APK        │
│   mobile.py      — мост, всегда JSON      │
│   dipkit/brain   — запрос к DeepSeek API  │   нужен интернет
│   dipkit/runner  — exec() в демон-потоке  │   подпроцессов на Android нет
│   dipkit/canvas  — градиенты, шум, текст, │
│                    фигуры, эффекты        │
└────────────────┬─────────────────────────┘
                 │ PNG + work.py + meta.json
┌────────────────▼─────────────────────────┐
│ os.environ["HOME"]  (files/ внутренней   │
│ памяти приложения)                        │
│   art/works/<дата>-<слаг>/art.png        │
└──────────────────────────────────────────┘
```

Общий движок лежит в `../python` — **тот же самый код**, что запускается на ПК.
Chaquopy забирает эту папку целиком (`srcDir("../../python")` в `app/build.gradle.kts`),
поэтому портировать движок не пришлось: понадобилось только научить его путям
Android (`dipkit/paths.py`), шрифтам `/system/fonts` и запуску кода без подпроцессов.

## Почему именно такие версии

Это не произвольный выбор — каждая цифра во что-то упирается:

| Что | Значение | Почему |
|---|---|---|
| Python в приложении | **3.12** | для неё в репозитории Chaquopy есть готовые wheels и `numpy`, и `pillow` |
| `numpy` | **1.26.2** | последняя версия с wheel `android_21_arm64_v8a` |
| `pillow` | **11.0.0** | wheel помечен **`android_24`** → `minSdk` не может быть меньше 24 |
| `minSdk` | **24** | прямое следствие предыдущей строки |
| ABI | **arm64-v8a** | все современные телефоны; вторая архитектура удвоит размер |
| Java | **17** | требование Android Gradle Plugin 8.x |
| AGP | **8.9.3** | на 8.7.x сборка с Chaquopy падает с «state lock»; 8.9.x — [подтверждённое решение](https://github.com/chaquo/chaquopy/issues/1339) |
| Gradle | **8.11.1** | минимально нужный для AGP 8.9.3 |
| Chaquopy | **17.0.0** | поддерживает AGP 7.3.x–9.2.x |
| security-crypto | **1.1.0-alpha06** | нужен для шифрования ключа; в 1.1.x старый `MasterKeys.getOrCreate` удалён, поэтому используется `MasterKey.Builder` |

Версии пакетов прибиты гвоздями намеренно: с незакреплённым `pillow` pip может
попытаться собрать пакет из исходников и упасть.

## Как собрать APK

### Способ 1: GitHub Actions (рекомендуется)

Ничего ставить локально не нужно: SDK и Gradle подтянет облако.

1. Создай пустой репозиторий на GitHub (можно приватный).
2. Залей туда **корень проекта** (папку `ДИПСИК ХУДОЖНИК` целиком, вместе с
   `android/`, `python/` и `.github/`).
3. Открой вкладку **Actions** → workflow «Сборка APK» → **Run workflow**.
4. Через 10–20 минут в разделе **Artifacts** появится `dipseek-artist-apk`.
5. Скачай, распакуй и установи `app-debug.apk` на телефон
   (понадобится разрешить установку из неизвестных источников).

Первая сборка дольше: облако скачивает SDK, Gradle и колёса numpy/pillow.

### Способ 2: одна команда локально (без Android Studio)

Из корня проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\build-apk.ps1
```

Скрипт сам найдёт и, если нужно, скачает всё недостающее:

| Что | Откуда берётся |
|---|---|
| Java 17 | `JAVA_HOME`, `Program Files`, `PATH` |
| Python 3.12 | `DIP_PYTHON`, bundled-рантайм DSH (там ровно 3.12), `PATH` |
| Android SDK | `ANDROID_SDK_ROOT`/`ANDROID_HOME`, иначе скачает command-line tools и поставит platform + build-tools |
| Gradle 8.11.1 | из `PATH`, иначе скачает дистрибутив в `.tools` |

Перед первой сборкой полезно посмотреть план, ничего не скачивая
(работает офлайн):

```powershell
powershell -ExecutionPolicy Bypass -File .\build-apk.ps1 -DryRun
```

Полезные ключи:

```powershell
.\build-apk.ps1 -X86_64              # добавить архитектуру эмулятора
.\build-apk.ps1 -Python "C:\Python312\python.exe"
.\build-apk.ps1 -SdkRoot "D:\Android\Sdk"
```

**Про `-ExecutionPolicy Bypass`.** Windows по умолчанию запрещает запуск
неподписанных `.ps1`, поэтому прямой вызов `.\build-apk.ps1` даёт ошибку
«файл не имеет цифровой подписи». Варианты: запускать через
`powershell -ExecutionPolicy Bypass -File ...` (как выше) либо один раз разрешить
скрипты для текущего пользователя: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.

APK окажется в `android/app/build/outputs/apk/debug/app-debug.apk`.

### Способ 3: Android Studio

1. Установи Android Studio, открой папку `android/` как проект.
2. Studio предложит создать Gradle Wrapper — согласись (файл
   `gradle-wrapper.jar` в репозитории намеренно отсутствует: это бинарник,
   который нельзя создать без сети).
3. Нажми **Run**. Отдельно настраивать Python не нужно: Chaquopy сам ищет
   Python 3.12 по правилам своей платформы (`py -3.12` на Windows,
   `python3.12`/`python3` на Linux и macOS).
4. Если Python 3.12 лежит в нестандартном месте, допиши в `android/gradle.properties`:
   ```properties
   dip.python=C:/Python312/python.exe
   ```

### Способ 4: вручную, без скрипта

```powershell
$env:ANDROID_SDK_ROOT = "C:\Android\Sdk"
sdkmanager "platforms;android-35" "build-tools;35.0.0" "platform-tools"
sdkmanager --licenses

cd android
gradle -Pdip.python="C:/Python312/python.exe" :app:assembleDebug
```

Свойства, которые понимает проект:

| Свойство | Смысл |
|---|---|
| `-Pdip.python=<путь>` | какой Python 3.12 использовать для Chaquopy |
| `-Pdip.abis=arm64-v8a,x86_64` | какие архитектуры собирать |

Их можно прописать и в `android/gradle.properties` — тогда они действуют
для Android Studio тоже.

## Ключ DeepSeek

Ключ **не вшит в приложение и не должен быть**. APK — это zip: любой, кто его
скачает, достанет оттуда любую строку. Поэтому используется схема «принеси свой
ключ»:

* пользователь вводит ключ в приложении (кнопка **Ключ** в правом верхнем углу);
* ключ лежит в `EncryptedSharedPreferences` (шифрование через Android Keystore);
* наружу уходит только запрос к `api.deepseek.com` с этим ключом;
* если шифрованное хранилище недоступно, приложение не падает, а переходит на
  обычные настройки.

Ключ выдают на [platform.deepseek.com](https://platform.deepseek.com) → API keys.

## Что внутри APK

Примерно 30–50 МБ, и почти всё это не наш код:

| Часть | Ориентировочно |
|---|---|
| Python-интерпретатор Chaquopy (arm64) | ~10–15 МБ |
| numpy | ~5 МБ |
| pillow | ~0,6 МБ |
| Kotlin + Compose (без минификации) | ~4–6 МБ |
| наш движок `python/` (8 файлов) | ~100 КБ |

Уменьшить: добавить `isMinifyEnabled = true` и `isShrinkResources = true`
в `buildTypes.release`, собирать release вместо debug, оставить одну ABI
(уже сделано).

## Ограничения — честно

* **Нужен интернет.** Рисует телефон, но код пишет DeepSeek: без сети приложение
  бесполезно (кроме повторной отрисовки уже готового кода).
* **Нужен свой ключ** и, соответственно, оплаченный аккаунт DeepSeek.
* **Фотореализм не получится.** Это кодо-арт: постеры, обложки, абстракция,
  пиксель-арт, генеративная графика.
* **Приложение исполняет код, который сгенерировала модель.** На ПК запуск идёт
  в отдельном процессе с таймаутом; на Android подпроцессов нет, поэтому код
  выполняется в демон-потоке внутри приложения и может занять поток целиком
  (таймаут срабатывает, но «убить» поток нельзя). Риск ограничен правами
  приложения: без доступа к твоим файлам, звонкам и т.п.
* **Debug-APK подписан отладочным ключом.** Для Google Play нужен release
  со своим keystore.

## Если что-то пошло не так

| Симптом | Причина и что делать |
|---|---|
| `Current thread does not hold the state lock for root project` | Известный баг Gradle + Chaquopy ([chaquo/chaquopy#1339](https://github.com/chaquo/chaquopy/issues/1339)). Лечится двумя вещами: в `android/gradle.properties` **не должно быть** `org.gradle.parallel=true`, и AGP должен быть **8.9.x** с Gradle **8.11.1**. Обе проверяются `dip checkandroid` |
| `Could not find a version that satisfies the requirement` | pip не нашёл wheel. Проверь версии Python (3.12), пакетов и ABI — они зафиксированы выше |
| `No matching distributions available for your environment` | То же: обычно не совпал `minSdk` (нужен ≥ 24) или ABI |
| `No module named 'numpy'` / `'PIL'` в приложении | Пакет не попал в APK. Смотри блок `pip` в `app/build.gradle.kts`; в логах устройства ищи тег `python.stderr` |
| `Read-only file system` | Код пытается писать в текущую папку. Писать можно только в `os.environ["HOME"]` |
| `No address associated with hostname` | Нет `INTERNET` в манифесте или нет сети |
| Сборка падает на `buildPython` | На сборочной машине нет Python 3.12 — см. способы выше |
| Приложение падает при старте | Смотри Logcat, теги `python.stdout` / `python.stderr` |
| Иконка «квадратная» на старых Android | Это нормально: адаптивные иконки появились в Android 8 |

Перед локальной сборкой полезно выполнить `..\dip.cmd clean` — он убирает
`__pycache__` из `python/`, иначе кэш байткода попадёт в APK как данные.
В GitHub Actions этот шаг уже встроен.

## Проверка без сборки

Полноценную сборку заменить нельзя, но большинство опечаток ловится заранее:

```powershell
..\dip.cmd checkandroid    # проверки проекта, включая сам build-apk.ps1
..\dip.cmd mobiletest      # контракт моста: 13 проверок
..\dip.cmd simandroid      # движок в режиме Android: 12 проверок
..\dip.cmd selftest        # движок: 53 проверки, включая путь exec (Android)
```

`simandroid` — самый полезный из них. Chaquopy сообщает об Android наличием
`sys.getandroidapilevel`, поэтому тест подставляет эту функцию **до импорта
движка** и подменяет `HOME`. В результате на ПК выполняется ровно та ветка кода,
которая пойдёт в APK:

* все пути считаются от `HOME`, а не от папки проекта;
* движок сам выбирает `exec`, потому что `subprocess` на Android невозможен;
* PNG и миниатюра появляются в `HOME/art/works/`, галерея их видит;
* кириллица действительно рисуется пикселями, а не пустыми квадратами;
* `draw()` без ключа отвечает `need_key`, а не падает.

Этот тест ловит ошибки вида «путь посчитан один раз при импорте»: на ПК они
безвредны, а на телефоне означают запись в несуществующую папку.

`checkandroid` в частности сверяет, что

* **каждая функция, которую зовёт Kotlin, существует в `mobile.py`**;
* `srcDir` Chaquopy действительно указывает на существующий пакет `dipkit`;
* `build-apk.ps1` лежит в UTF-8 **с BOM** и без типографских тире (иначе
  Windows PowerShell 5.1 не разберёт файл — проверка чинит это сама);
* `build-apk.ps1` **разбирается настоящим парсером PowerShell** и проходит `-DryRun`;
* скрипт передаёт в Gradle ровно те свойства (`dip.python`, `dip.abis`),
  которые Gradle читает;
* **разбор ошибок сборки опознаёт известные сбои** — проверяется на синтетических
  логах Gradle.

## Если сборка упала

`build-apk.ps1` сохраняет полный лог в `.tools/build-log.txt` и сам пытается
объяснить причину — ищет известные сигнатуры и печатает подсказку, например:

```
  Похоже на известную проблему:
   * pip не нашёл колесо под Android. Почти всегда дело в версии Python:
     Chaquopy собирает колёса строго под неё. Нужен Python 3.12.
```

Разобрать любой лог вручную можно так:

```powershell
powershell -ExecutionPolicy Bypass -File .\build-apk.ps1 -ExplainLog .tools\build-log.txt
```

## Что менять дальше

* **Тестировать на эмуляторе** — `.\build-apk.ps1 -X86_64`.
* **Release-сборка** — создай keystore, добавь `signingConfigs` и собирай
  `assembleRelease`.
* **Правка кода прямо в приложении** — кнопка «Код» показывает сгенерированный
  скрипт, а мост уже умеет `render` с произвольным кодом: осталось сделать поле
  редактируемым.
* **История и удаление работ** — в `mobile.py` есть `works`, `work_code` и
  `delete_work`; интерфейс пока показывает только ленту миниатюр.
* **Диффузионный бэкенд** — тогда в приложении появится фотореализм; движок
  и мост к этому готовы.
